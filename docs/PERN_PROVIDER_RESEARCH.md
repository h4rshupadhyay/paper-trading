# Market-data provider research

Research date: 3 November 2026. **No candidate is validated for execution in this app.** This bounded pass reviewed public, official documentation only; it used no account signup, paid subscription, authenticated feed, production service or database test. Product documentation establishes a shortlist, not observed freshness or entitlement. Europe here means the **Germany/Xetra sample only**.

## Acceptance boundary

The [design spec](superpowers/specs/2026-11-02-paper-trading-pern-design.md) and [existing validation report](PERN_PROVIDER_VALIDATION.md) require provider-observed quotes aged ≤60 seconds, confirmed current regular session, metadata-backed major currency units (including GBp ×0.01 → GBP), INR-directed FX aged ≤24 hours, and complete split/dividend change detection for held/live-order instruments. Fetch time cannot renew an observation; up to five seconds of future skew is allowed. Unknown session/action/unit evidence must block execution. Raw execution prices and chart semantics must agree; adjusted history is not an action feed. Current Yahoo remains display-only with `session=UNKNOWN` and `tradable=false`.

## Coverage and freshness shortlist

| Region / venue | Twelve Data public coverage listing | IBKR documented live subscription route |
| --- | --- | --- |
| US equities | Real-time/EOD/OTC categories; precise venue/feed still needs selection | Relevant NYSE Network A, Network B or NASDAQ Network C streaming entitlement |
| India / NSE | XNSE: EOD | National Stock Exchange of India, Capital Market Segment |
| UK / LSE | XLON: EOD | LSE UK |
| Germany / Xetra | XETR: EOD | Spot Market Germany (Frankfurt/Xetra) |
| Japan / Tokyo | XJPX: delay shown as “–”, not a realtime promise | Tokyo Stock Exchange |
| Hong Kong | XHKG: delay shown as “–”, not a realtime promise | Hong Kong Securities Exchange (Stocks, Warrants & Bonds) |

Sources: [Twelve Data exchange directory](https://twelvedata.com/exchanges), [IBKR subscription/delay table](https://www.interactivebrokers.com/en/pricing/market-data-pricing.php). These are catalog entries, not account-specific access proofs. Twelve Data's separate Cboe Europe feed does not prove primary LSE/Xetra observations. IBKR lists delayed alternatives of 15 minutes for NSE/LSE/Xetra/HK and 20 minutes for Tokyo; those cannot meet this app's threshold.

### Twelve Data: useful REST interface; standard coverage fails six-region execution

Its documented [time series](https://twelvedata.com/docs/market-data/time-series) supports explicit `adjust=none`; the default is split-adjusted. [Market state](https://twelvedata.com/docs/markets/market-state) returns exchange MIC and an open flag, but the reviewed schema does not establish a timestamped per-instrument regular-session attestation through auctions, lunch breaks, halts and exceptional closures. [Splits](https://twelvedata.com/docs/fundamentals/splits) and [dividends](https://twelvedata.com/docs/fundamentals/dividends) endpoints provide event histories on eligible plans; their existence does not prove complete six-venue coverage or correction notification before execution.

The [exchange-rate endpoint](https://twelvedata.com/docs/currencies/exchange-rate) includes pair, rate and Unix observation timestamp. That is a plausible FX interface, but USD/INR, GBP/INR, EUR/INR, JPY/INR and HKD/INR availability/direction/freshness were not probed. No reviewed source establishes the required LSE quote-unit mapping. Missing: eligible API key/plan, explicit venue entitlements and usage rights, all five FX samples, unit evidence and complete action/session semantics. A custom offering could differ; no such offering is evidenced here. **Do not choose the standard plan as a six-region realtime fix.**

### Interactive Brokers: strongest entitlement lead; not a drop-in data vendor

IBKR distinguishes live, frozen, delayed and delayed-frozen data in its [legacy official API reference](https://interactivebrokers.github.io/tws-api/market_data_type.html). A live subscription is necessary; frozen/delayed responses must be rejected. Its current [Web API guide](https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/) requires a relevant subscribed username, instrument permission and authorized brokerage session. Snapshot data requires a preflight; connection/update timestamps must not be assumed to be the last trade's observation time. The adapter must select and verify an execution-price timestamp field.

Current [contract documentation](https://www.interactivebrokers.com/docs/tws-api/doc/contracts/details) supplies `TradingHours`, `LiquidHours` and timezone. These are useful schedules, not by themselves proof of current regular-session status. A confirmed live status/phase source and halt behavior remain unresolved. The [legacy history reference](https://interactivebrokers.github.io/tws-api/historical_bars.html) says `TRADES` is split-adjusted and `ADJUSTED_LAST` split/dividend-adjusted: neither should silently replace this app's raw history. The [legacy WSH documentation](https://interactivebrokers.github.io/tws-api/fundamentals.html) describes a separately subscribed event calendar containing splits and dividends; complete instrument coverage, corrections, backfill and notification latency remain unproven. These legacy pages explicitly direct readers to current documentation; verify behavior against the selected installed API version.

FX needs separate contract-level proof: [current subscription docs](https://www.interactivebrokers.com/docs/general/market-data-subscriptions/introduction) exempt forex from additional data subscriptions, but do not establish these five INR-directed pairs. Unit scaling also needs instrument-specific evidence; a currency label alone is insufficient. [Subscription setup](https://www.ibkrguides.com/orgportal/usersettings/marketdatasubscriptions.htm) distinguishes TWS, alternative display and non-display/API applications with possible agreements. Missing: an eligible account/user, API session, funded subscription eligibility, venue/API/non-display permissions and permitted app distribution. NSE access/account eligibility must be confirmed explicitly; [IB India account information](https://www.interactivebrokers.co.in/en/accounts/individual-account-india.php) describes an NSE-only resident account category. Do not infer one user's global access from the catalog or personal subscriptions' suitability for a shared web app.

### EODHD: display/history candidate; global delayed quotes fail

The [Live OHLCV API](https://eodhd.com/financial-apis/live-ohlcv-stocks-api) explicitly delays stocks 15–20 minutes, with roughly one-minute FX updates. Its comparison table identifies realtime WebSocket equities as US coverage; a transport-latency claim does not prove realtime coverage for the other five venues. [Exchange catalog APIs](https://eodhd.com/financial-apis/exchanges-api-list-of-tickers-and-trading-hours) can resolve symbol coverage, but six representative contracts were not queried. The [provider's disclaimer](https://eodhd.com/) also describes indicative prices and warns of suitability limitations for trading; an execution-grade agreement/source clarification is required.

[EOD history](https://eodhd.com/financial-apis/api-for-historical-data-and-volumes) separates raw OHLC from adjusted close (volume is split-adjusted). Its [actions API](https://eodhd.com/financial-apis/api-splits-dividends) supplies dividend/split histories, and [exchange metadata](https://eodhd.com/financial-apis/exchanges-api-trading-hours-and-stock-market-holidays) includes open status, hours and holidays. None proves timely complete action detection or per-instrument regular-session attestation. Missing: API credentials/coverage samples, all INR pairs, LSE unit scaling, completeness/correction contract and appropriate usage rights. Even resolving these would not make the documented global delayed feed pass ≤60 seconds.

## Grounded next step

Keep live eligibility disabled. Prioritize an **IBKR feasibility/evidence check**, before implementing a new adapter or purchasing anything: obtain account-specific confirmation of all six venue API entitlements, app usage rights, primary venue identities, exact quote observation timestamps/units, five INR FX pairs, live regular-session status, raw chart strategy, and complete split/dividend coverage with corrections. If actions or status require another licensed source, record that dependency explicitly; none of the three is proven self-sufficient.

Only after credentials/permissions are supplied, run bounded read-only probes during each venue's regular session for AAPL, RELIANCE/NSE, VOD/LSE, SAP/Xetra, Toyota/Tokyo and Tencent/HK. Persist raw metadata and provider timestamps alongside normalized values, measured ages, feed type and status. Exercise lunch/close/holiday/halt and disconnect cases, stale FX, a GBp instrument, known split/dividend plus correction/replay cases, and all held/order instruments under the actual quota. A single symbol or fresh tick cannot validate a whole region. Require documented completeness plus reconciliation evidence; empty action arrays cannot establish absence. Enable each region only after every gate passes in the actual adapter, retaining explicit unavailable reasons elsewhere.
