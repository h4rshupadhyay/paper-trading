# Free-tier provider feasibility

Research date: 3 November 2026; provider documentation refreshed 4 November. Budget: **free tier only**. This bounded pass used official documentation, terms, provider-owned SDK source and public endpoints. No account was created, credentials obtained, subscription purchased, or provider contacted. No authenticated equity probe ran. This supplements [prior provider research](PERN_PROVIDER_RESEARCH.md), without reopening its rejected delayed feeds.

**Finding: no reviewed free offering establishes all six regions or even a complete US execution acceptance path. Alpaca Basic is the clearest free-signup candidate for a US-only IEX evidence probe.** This is a test recommendation, not permission to enable LIVE. Missing evidence remains a blocking result; free pricing does not waive the existing timestamp/session/unit/FX/action gates.

## Region boundary

“Europe” below means Germany/Xetra only. A US ADR, an alternative European venue, or international fundamentals do not establish primary-venue equity coverage.

| Required primary region | Alpaca Basic documented free realtime scope | Finnhub free evidence recovered in this pass | Alpha Vantage free execution suitability |
| --- | --- | --- | --- |
| US | US stocks/ETFs, IEX only; executable probe after signup | Real-time quote/trade endpoints documented; free entitlement/feed not verified | Default quotes EOD; realtime US quotes premium |
| India / NSE | Outside documented Basic US securities scope | No verified free NSE realtime entitlement | No verified ≤60-second NSE observations |

| Germany / Xetra | Outside documented Basic US securities scope | No verified free Xetra realtime entitlement | No verified ≤60-second Xetra observations |

Sources and limits: Alpaca's [subscription/authentication documentation](https://docs.alpaca.markets/us/docs/about-market-data-api) specifies US securities, free Basic, realtime IEX, 30 websocket symbols and 200 historical API calls/minute. It distinguishes personal Trading API from partner Broker API; all equity market-data endpoints need authentication. Current first-party Finnhub references are readable and describe US real-time endpoints, but do not establish free-tier entitlements; international real-time stock prices are Enterprise-only. See the [Finnhub assessment](#finnhub-keep-as-a-conditional-lead) for detail. Alpha Vantage's [documentation](https://www.alphavantage.co/documentation/) says default global quotes update at day end, with realtime/delayed US entitlement premium-only; global API naming is not a six-region realtime promise.

## Alpaca Basic: concrete free prerequisite, incomplete acceptance

[Paper Only accounts](https://docs.alpaca.markets/us/docs/paper-trading) are documented as globally available through email signup, with IEX data entitlement. A funded live brokerage account is not the documented prerequisite for this paper-only data experiment. The user must create their own account and supply a key/secret securely. No anonymous equity demo was identified; do not confuse Alpaca's paper order simulation with this application's provider-backed execution acceptance.

The [market-data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) explicitly supports latest IEX trades without the SIP subscription, exposes provider `trade.t`, and says latest endpoints return data as received. Recent SIP data requires a paid entitlement. An IEX trade is one venue's observation, not the consolidated latest US trade; sparse IEX observations can exceed 60 seconds even during an open market. This is an inference from the single-venue scope, to be measured rather than waived.

The [latest-trades reference](https://docs.alpaca.markets/us/reference/stocklatesttrades-1) accepts explicit `feed=iex` and ISO 4217 `currency` (default USD), and excludes conditions that do not update bar prices, including odd lots. Thus its “latest” is a filtered eligible trade. Record that price definition and retain raw USD prices; do not treat bid/ask time, bar start or fetch time as trade observation time. This proves no GBp/LSE conversion rule.

The [stock stream](https://docs.alpaca.markets/us/docs/real-time-stock-pricing-data) documents RFC3339 trade timestamps, condition/exchange fields, automatic trade corrections/cancel messages, and timestamped per-security halt/resumption statuses. Status access depends on subscription; the page also directs production enablement to sales. **Free Basic status entitlement, initial status before the first event, reconnect recovery and a regular-session attestation remain unproven.** Trade correction messages are not corporate-action corrections. A calendar or account clock alone cannot establish that a particular security is currently unhalted.

The [corporate-actions REST endpoint](https://docs.alpaca.markets/us/reference/corporateactions-1) includes split/dividend types and pagination; default `data_quality=complete` excludes some early incomplete records. That parameter name describes record quality, not exhaustive instrument coverage. The same reference explicitly warns that corporate-action creation time is not guaranteed and receipt/processing can delay availability after announcement; a free key cannot remove that timeliness/completeness blocker. The [corporate-actions SSE endpoint](https://docs.alpaca.markets/us/reference/subscribetocorporateactionseventssse) documents insert/update/delete mutations and replay using time/event IDs, including inclusive replay requiring deduplication. These are promising correction/recovery mechanics. **Basic entitlement, action publication timeliness, complete held/order-instrument coverage and replay retention have not been established.** `non_us` support in an action schema does not prove all five required non-US venues or realtime equity access.

[Alpaca's published terms](https://files.alpaca.markets/disclosures/library/TermsAndConditions.pdf) describe personal/noncommercial use. They also require 30 days' advance written notice before making a user application available to others and reserve the right to restrict or disallow its connectivity; the [disclosure library](https://alpaca.markets/disclosures) lists additional market-data agreements. Public or multi-user redistribution must not be assumed from free account access. This pass establishes a personal research route, not rights for a shared production website. No INR FX feed was established from Basic.

## Finnhub: keep as a conditional lead

Current first-party material narrows the scope but does not establish a usable free plan. The official [Quote API reference](https://finnhub.io/docs/api#quote) says it returns real-time quote data for **US stocks** and says real-time international stock prices are available to **Enterprise** clients through a partner feed. Its [trade WebSocket reference](https://finnhub.io/docs/api#websocket-trades) describes real-time trades for US stocks, forex and crypto, with a millisecond trade timestamp; its title mentions “US Full SIP, LSE,” but the body does not specify an LSE entitlement or a plan. Therefore the documentation supports US real-time *endpoint scope*, not a free US exchange/feed entitlement, and it supplies no free real-time entitlement for NSE, LSE, Xetra, Tokyo or Hong Kong. In particular, the Enterprise limitation blocks treating a global symbol catalogue or an international quote response as free real-time primary-venue coverage.

The readable [pricing page](https://finnhub.io/pricing) now exposes paid market-data product prices and exchange selectors (including US, Indian, LSE and German/Xetra), but it does not publish a free-tier feature matrix, quota, venue-by-venue latency, or real-time entitlement. Its marketing metadata calls Finnhub “Free APIs for realtime stock, forex, and cryptocurrency,” which is too general to override the Quote API's US/Enterprise distinction. Do not repeat an unverified “60 calls/minute” quota or claim a particular free US feed. The [provider-owned Python SDK](https://github.com/Finnhub-Stock-API/finnhub-python) still establishes only that an API key is required and that quote, symbol, dividend, split and forex methods exist; the [current API reference](https://finnhub.io/docs/api) labels stock candles, dividends and splits as premium, so those endpoints cannot establish a free corporate-action or intraday-history path.

[Finnhub's official terms](https://finnhub.io/terms-of-service) remain material: listed plans are personal unless explicitly stated otherwise; business use even internally requires written approval, and redistribution/sharing data or derived results requires written approval. Professional subscribers are excluded from personal plans. The terms disclaim completeness and require deletion when the subscription to that data ends. Its [enterprise offering](https://api.finnhub.io/pricing-startups-and-enterprise) advertises commercial redistribution rights and all-exchange coverage through sales; it is not a free route.

Before choosing Finnhub over Alpaca, obtain a current written free entitlement that names the exact US feed and explicitly covers the intended personal use. Then test exact quote timestamps, primary venues, per-security status, raw units, five INR pairs and action mutations. No authenticated probe was run here. **US free availability, all five non-US free real-time primary-venue entitlements, free quota, venue latency, correction/replay behavior, status coverage and action completeness remain unproven; Finnhub cannot presently close either the US or six-region gate.**

## Alpha Vantage: free signup useful for display/research

[Official support](https://www.alphavantage.co/support/) specifies 25 free API requests/day and says realtime and 15-minute-delayed US market data are premium-only. The [API reference](https://www.alphavantage.co/documentation/) offers a free-key signup, global symbol search, exchange-rate fields including refresh time, and premium adjusted daily history. Adjusted history is not evidence of complete split/dividend change detection. The quota cannot sustain continuous ≤60-second equity polling across held/live-order instruments.

A public [IBM GLOBAL_QUOTE demo request](https://www.alphavantage.co/query?function=GLOBAL_QUOTE&symbol=IBM&apikey=demo) returned only an `Information` message directing free-key signup during this pass, not a quote. A [USD/INR demo request](https://www.alphavantage.co/query?function=CURRENCY_EXCHANGE_RATE&from_currency=USD&to_currency=INR&apikey=demo) could not be fetched by the research tool; that is not an API rejection or a pair-support result. No market observation was validated. A free key would permit a bounded display/FX experiment, not fix the known free quote freshness failure.

## No-signup auxiliary FX experiment

[ExchangeRate-API Open Access](https://www.exchangerate-api.com/docs/free) documents no key, daily updates, attribution, caching and rate limiting. It supports replacing the base currency in `https://open.er-api.com/v6/latest/USD`, returning INR-directed `rates.INR` from each base. Its [terms](https://www.exchangerate-api.com/terms) allow personal/commercial end use but prohibit redistribution/programmatic exchange-rate services and explicitly discourage transaction/financial-data use. Treat it as an informational paper-conversion candidate requiring suitability review, not an execution-approved FX source.

The [public USD response](https://open.er-api.com/v6/latest/USD) was retrieved without signup: `base_code=USD`, `rates.INR=94.928524`, `time_last_update_unix=1793664151` (`2026-11-03 00:02:31 UTC`), next update `2026-11-04 00:22:21 UTC`. At the nearby tool clock reading `2026-11-03 14:30:17 UTC`, the reported update age was about 14h28m. This is a timestamp/shape observation, not independent rate accuracy or upstream market-observation verification. The next scheduled update is over 24 hours after the last, so a strict ≤24-hour gate can have a gap. GBP/EUR/JPY/HKD base responses were not probed. A server update timestamp must not silently become a validated underlying FX observation timestamp.

## Executable next step under zero budget

1. Keep all regions ineligible for LIVE. Choose **Alpaca Paper Only / Basic / IEX** for the first personal, read-only US probe if the user elects free signup. No subscription or deposit is part of this recommendation. Prerequisite: user-owned credentials and applicable account/data agreements; do not put secrets in this report or commit them.
2. With those credentials, request `GET https://data.alpaca.markets/v2/stocks/trades/latest?symbols=AAPL&feed=iex&currency=USD` using `APCA-API-KEY-ID` and `APCA-API-SECRET-KEY` headers. During US regular session, persist raw payload, feed, symbol, units, provider `t`, receipt time and measured age. This request is a prepared plan and **was not run**. Enforce the existing ≤60-second/future-skew rule without renewing observation time on cache reads.
3. Establish Basic status and action permissions before adapter implementation: test status subscription/initial-state/reconnect behavior and corporate-action REST/SSE authorization; retain explicit forbidden/unknown outcomes. Reconcile raw charts against the chosen filtered IEX trade semantics; verify splits, dividends, action edits/deletes, replay and complete held/order coverage. An empty action response proves no completeness.
4. Separately test USD/INR and, only for future venue work, GBP/EUR/JPY/HKD→INR using an acceptable free source. Establish what its timestamp actually measures and enforce ≤24 hours. No equity feed here supplies the GBp→GBP metadata proof.

Success for step 2 would establish only one instrument's sampled IEX freshness. It would not enable US execution until status, rights, FX, units, chart semantics and complete action detection pass, and would establish nothing about NSE/LSE/Xetra/Tokyo/Hong Kong. **If the requirement remains all six primary markets with every existing acceptance gate, this research provides no qualifying free solution; preserve the unavailable reasons rather than relaxing acceptance.**
