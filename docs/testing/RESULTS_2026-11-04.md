## Defects found and corrected

### 1. Raw rejected-order code in the trade form

Fresh empty account → AAPL → Trade → Sell → quantity 1 → submit displayed `INSUFFICIENT_POSITION`. The server correctly stored one REJECTED order. Before the failing readability assertion, SQL confirmed identical cash balance, cash sequence, ledger movement count, execution count and position count.

UI-026 first failed on the actual visible error, then passed after mapping rejection codes to plain messages. Insufficient shares now says **“You don't have enough shares to sell.”** The adapter also supplies readable text for insufficient cash, disabled accounts, too-small/too-large values and unknown reasons, including the history tooltip. Backend error codes remain unchanged. The new direct browser regression covers insufficient shares; the other mapping branches/history tooltip do not each have a new browser case.

Affected source: `frontend/src/services/api.js`, `frontend/src/services/contracts.js`. No execution, balance or eligibility logic changed.

### 2. Docker-version-dependent nginx test setup

The latest committed [hosted run](https://github.com/h4rshupadhyay/paper-trading/actions/runs/41725732523) failed both nginx forwarding tests while nginx itself started normally. Original diagnostics omitted the failed client's stderr. A separate Docker 28.5.2 daemon reproduced the underlying test-client failure:

```text
auto subnet result: exit 125
user specified IP address is supported only when connecting to networks with user configured subnets
explicit subnet result: exit 0, client started
```

The local Docker 29.8.1 daemon accepted the original automatic-subnet setup, explaining the local/hosted difference. The harness now lets Docker choose an unused subnet, then recreates its own empty, uniquely named network with that subnet explicitly configured before joining clients. The complete deployment suite subsequently passed on both daemon versions. Readiness failures now include the client's exit/stdout/stderr and nginx logs. Production nginx trust policy was unchanged.

### 3. Compose missing-secret assertion depended on traversal order

The hosted failure expected `Set PAPER_`, but Compose reported missing `CSRF_SECRET` first. The configuration correctly failed closed; the assertion was wrong. It now accepts any required secret in the all-missing case and separately removes **each of the five required values**, for both default and explicit Compose entry points, checking that the corresponding missing value is reported. Tests render dummy configuration only.

### 4. Empty browser filter could falsely pass

Independent review found that `AUDIT_CASE=UI-NOT-A-CASE` exited 0 with `0 passed, 0 failed`. This was reproduced, then corrected with a nonzero-case assertion. The same input now exits 1; matching filters continue to run and pass. Cleanup executes in both cases.

Initial development failures in the new tests also exposed incorrect test-driver assumptions: hidden delete controls needed hover, the styled side switch required its visible label, an expected picker message differed, and a seeded ledger query sorted a text alias lexically. Those were test authoring errors and are not counted as application defects. Expectations retain persisted-state assertions; the real rejection-copy regression was preserved separately.

## Isolation, seeds and cleanup

Every backend/browser write uses `createHarness()` and its exact allowlisted admin URL on loopback port 55439. The harness creates random databases with owner/runtime roles, migrates them and drops them on cleanup. Each new browser scenario gets a fresh account and browser context. Required SELL holdings, history orders and notifications are created through actual services/APIs; the analytics fixture copies a real valuation into an earlier sample bucket. Seeding is setup, not evidence that a form works.

All market tests are offline or use controlled local provider responses. No real orders, external messages or test writes were sent to an application account. The live Compose stack and `.env.pern-compose.local` were not used for seeds. The Docker 28 probe used a separate disposable daemon with no application volumes; its container and anonymous volumes were removed after verification. Existing user draft provider documents were left untouched.
