# Same-application demo user

Username `demo` is a normal user in the existing application database. See [creation instructions](../../README.md#demo-user-with-populated-data). Normal authentication, trading gates and shared current market data remain in use.

## Historical provider data

The seed uses an internal, fixed-symbol `/demo-history` export from the yfinance sidecar: one month of AAPL, MSFT, RELIANCE.NS and USDINR=X unadjusted daily history. Missing, invalid, future or stale observations fail the seed before writes. There is no production fallback to test fixture prices. The test fixture is explicitly confined to `apps/server/test/fixtures`.

Only completed sessions are admitted, conservatively after the next source-local midnight. Equity reference times use regular session end (later than actual close on early-close days). FX daily closes become available at the following source-local midnight. Simulated fills use an as-of FX close, carried for at most four days; historical snapshots similarly use only prices/rates available by the sample cutoff. Splits or dividends in the completed source window cause refusal until properly modeled.

Five simulated trades preserve the original demonstration: buys of AAPL 10, MSFT 4, RELIANCE 20, then partial sales of AAPL 3 and RELIANCE 5 on actual sessions spread across the window. These are paper executions at reference closing prices, not claims of real execution events. Decimal SQL computes settlements, moving average costs, cash movements, realized P/L, remaining positions and daily portfolio history. Historical samples are marked stale, not fresh live observations. The provenance journal and a private downloaded-data artifact identify source dates and retrieval time.

AAPL buy limit is 2% below its latest completed close; RELIANCE sell stop is 5% below; MSFT buy stop-limit has a stop 2% above and a limit 2.5% above. New seeds include affordable one-share orders, meaningful alerts, sensible terminal examples, watchlists and three journal/research/provenance notes. Current market movement may subsequently fill or invalidate orders normally. Values and account cash vary with the source observations; there is no fixed expected production balance.

## Guarded upgrade of the original demo

The explicit `--upgrade` CLI requires owner maintenance credentials through `DEMO_UPGRADE_DATABASE_URL`; normal runtime grants remain unchanged. It refuses production and active worker batches, holds the same advisory lock used by the worker across refresh/trading/alerts/sampling, locks the reserved demo account/orders, verifies original execution prices, amounts, timestamps, costs, order fingerprints, positions, six ledger entries and exact original cash/sequence, and refuses later trading or changed accounting. A required backup callback saves affected rows plus source observations to a mode-0600 JSON file before writes. A backup failure or later write failure rolls back the transaction.

Only recognized history is replaced. Identity/password, user-edited notes and cancelled orders are preserved. Untouched open seed thresholds and alerts are updated; valuation samples based on superseded costs are invalidated and rebuilt. Historical alert/notification reference prices are made consistent with the replacement history. Original cancelled examples can retain their old prices because cancellation is a user edit. A v2 order marker prevents repeat upgrades from rewriting subsequent activity even if a journal note is edited or deleted. Other users and shared market observations are untouched.
